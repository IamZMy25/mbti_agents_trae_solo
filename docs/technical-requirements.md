# 多Agents头脑风暴/辩论赛项目技术需求文档

## 1. 项目概述

本项目旨在创建一个多Agents进行头脑风暴或辩论赛的系统，每个Agent都具有不同的MBTI人格特征。系统支持三种会话模式：头脑风暴、辩论赛和闲聊，用户可以通过前端界面与这些智能体进行交互。

### 1.1 核心功能
- **多MBTI人格智能体**：每个智能体都具有独特的MBTI人格特征
- **三种会话模式**：头脑风暴、辩论赛和闲聊
- **实时交互**：通过前端状态管理实现实时更新
- **数据持久化**：使用IndexedDB存储会话信息、消息记录、观点和投票
- **可配置性**：用户可以配置LLM API和参与的智能体

### 1.2 技术栈
- **前端**：React + Redux Toolkit + Ant Design + IndexedDB
- **后端**：Python 3.11.14 + FastAPI + LangChain 1.2.10 + LangGraph
- **部署**：静态网站（Vercel/Netlify/GitHub Pages） + 云端LLM API

## 2. 需求分析

### 2.1 前端需求
1. **界面设计**：微信/QQ风格的聊天界面
2. **配置功能**：配置LLM的API
3. **会话管理**：
   - 查看已发生过的头脑风暴/辩论赛/闲聊
   - 建立新的头脑风暴/辩论赛/闲聊
4. **交互控制**：
   - 开始/暂停讨论
   - 发送消息
5. **数据存储**：
   - 使用IndexedDB存储用户配置、会话信息、消息记录、观点和投票
   - 确保数据的持久化和一致性

### 2.2 后端需求
1. **Agent设计**：
   - Host Agent：主持人智能体，用于推进讨论，总结观点
   - MBTI Agent：带有MBTI人格的智能体
2. **模式实现**：
   - 头脑风暴Graph：包含开场白、第一轮观点表达、第一轮讨论、观点投票、第二轮讨论、总结等节点
   - 辩论赛Graph：包含开场、正方立论、反方立论、自由辩论、总结陈词、结果宣布等节点
   - 闲聊模式：有记忆的MBTI对话
3. **LLM调用**：
   - 封装LLM API调用，支持并发调用
   - 处理API密钥管理和请求限流
4. **API服务**：
   - 提供简单的RESTful API，处理LLM调用和会话管理

## 4. 数据存储设计

### 4.1 IndexedDB存储结构

**1. 用户信息**：
- 存储用户配置（如LLM API Key）

**2. 会话信息**：
- 会话ID
- 会话类型（brainstorm、debate、chat）
- 主题
- 状态（created、running、paused、completed）
- 创建时间
- 更新时间

**3. 会话成员**：
- 会话ID
- 智能体类型（user、host、mbti）
- 智能体ID（用户ID或MBTI类型）
- 角色（辩论中使用：pro、con）

**4. 消息记录**：
- 消息ID
- 会话ID
- 发送者类型（user、host、mbti）
- 发送者ID（用户ID或MBTI类型）
- 内容
- 时间戳

**5. 观点记录**：
- 观点ID
- 会话ID
- 内容
- 创建时间

**6. 投票记录**：
- 投票ID
- 会话ID
- 观点ID
- 投票者ID（MBTI类型）
- 投票时间

### 4.2 数据操作
- **插入操作**：记录会话、消息、观点和投票
- **查询操作**：获取历史会话、消息记录、观点和投票结果
- **更新操作**：更新会话状态和用户配置
- **删除操作**：清理过期数据

## 5. 部署方案

### 5.1 前端部署
- **静态网站部署**：
  - GitHub Pages：免费，适合静态网站
  - Vercel：免费，部署简单，支持自动构建
  - Netlify：免费，支持自动构建和部署

### 5.2 后端部署
- **云端部署**：
  - Vercel Serverless Functions：免费，适合轻量级API
  - Netlify Functions：免费，适合轻量级API
  - AWS Lambda：按需付费，适合高并发场景

### 5.3 运行环境
- **本地运行**：
  - 前端：npm run dev
  - 后端：uvicorn app.main:app --reload

- **云端运行**：
  - 前端：部署到静态网站托管服务
  - 后端：部署到Serverless Functions

## 6. 安全考虑

### 6.1 前端安全
- **API密钥管理**：
  - 存储在IndexedDB中，加密存储
  - 不在网络上传输，只在本地使用

### 6.2 后端安全
- **API访问控制**：
  - 实现简单的API密钥验证
  - 限制请求频率，防止滥用

### 6.3 数据安全
- **数据隔离**：
  - 每个用户的数据只存储在本地，不共享
  - 后端不存储用户数据，只处理临时请求

## 7. 性能优化

### 7.1 前端优化
- **IndexedDB优化**：
  - 使用索引加速查询
  - 批量操作减少数据库事务
  - 合理设计数据结构，减少冗余

### 7.2 后端优化
- **LLM调用优化**：
  - 缓存LLM响应
  - 批量处理相似请求
  - 合理设置超时和重试机制

### 7.3 网络优化
- **API请求优化**：
  - 减少不必要的API调用
  - 压缩请求和响应数据
  - 使用适当的缓存策略
